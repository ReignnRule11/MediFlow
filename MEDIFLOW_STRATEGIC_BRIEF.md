## 1. COMPLETE USER JOURNEY

### User Personas & Flows

#### 1.1 **Patient User Journey** (Primary Flow)
```
AWARENESS → ONBOARDING → UPLOAD → PROCESSING → DISCOVERY → ACTION → ENGAGEMENT
```

**Phase 1: Awareness & Signup**
- Patient lands on MediFlow homepage
- Patient signs up via email/phone
- Patient provides basic health context (chronic conditions, allergies, current meds if known)

**Phase 2: First Upload (Critical Experience)**
- Patient clicks "Upload Medical Document"
- Patient takes photo/uploads PDF (prescription, lab report, discharge summary, etc.)
- System shows: "Processing your document... extracting key information"
- **AI Moment 1:** OCR extracts:
  - Medications (drug name, dosage, frequency)
  - Lab values (test name, result, reference range, date)
  - Doctor notes & diagnoses
  - Appointments & procedures
  - Allergies & contraindications

**Phase 3: Smart Timeline Build**
- Patient sees AI-generated **"Your Health Timeline"**
  - Chronological view of all medical events
  - Color-coded by category (meds, labs, appointments, procedures)
  - Links between related events (e.g., "High cholesterol lab → Statin prescribed")

**Phase 4: Discovery (Wow Moment)**
- **AI Feature 1:** Patient taps on medication → AI explains:
  - "What is this drug?" (plain English)
  - "Why are you taking it?" (based on context)
  - "Common side effects" (curated for your age/conditions)
  - "Drug interactions" (compared against other meds you're on)
- **AI Feature 2:** Patient sees **Medication Conflict Alert**
  - Red alert: "⚠️ Your Aspirin (from cardiology) conflicts with your Ibuprofen (for pain)"
  - Explanation: "Both thin blood; combined use increases bleeding risk"
  - CTA: "Discuss with your doctor"
- **AI Feature 3:** Lab Report Summary
  - Patient uploads cholesterol panel
  - AI shows: "Your LDL is 180 (high). Normal is <100. This explains your recent Statin prescription."

**Phase 5: Ongoing Engagement**
- **Medication Reminders:** "Time for your morning medications (3 pills)"
- **Appointment Reminders:** "Dr. Smith in 2 days at 10 AM. Upload insurance card?"
- **Health Insights:** "You've had 3 labs in 6 months. Trends show improving kidney function 📈"

**Phase 6: Doctor Visit Prep**
- Before appointment, patient sees: **"Ready for Dr. Smith?"**
  - Pre-visit summary generated by AI
  - Patient can mark "Questions to ask" and AI prioritizes them
  - Upload recent vitals (if home BP monitor, Fitbit, etc.)

#### 1.2 **Doctor User Journey** (Secondary Flow)
```
PATIENT_LOOKUP → SUMMARY_REVIEW → CONSULTATION → NOTES → PRESCRIBE
```

**Phase 1: Patient Lookup**
- Doctor logs in / searches patient by name/ID
- Doctor clicks "View MediFlow Profile"

**Phase 2: Pre-Consultation Summary** (THE KILLER FEATURE)
- **AI Feature 4:** Doctor sees **one-page AI-generated summary**:
  - Patient photo + name + age + allergies (red banner)
  - Chief complaints & recent visits (last 6 months)
  - Current medications (flagged: any new, stopped, or conflicting)
  - Recent lab values with trends (with normal ranges highlighted)
  - Chronological timeline of events
  - **Key insight:** "Patient has been on Lisinopril for 3 years, but last lipid panel shows worsening lipids despite Statin—consider medication adjustment"
  - Generated in <5 seconds; doctor has 30 seconds before patient walks in

**Phase 3: Consultation**
- Doctor takes notes (free text, voice-to-text, or structured templates)
- If doctor prescribes new medication:
  - System auto-checks: "⚠️ New drug conflicts with patient's Metformin and Grapefruit juice"

**Phase 4: Post-Visit**
- Doctor uploads prescription or discharge notes
- Notes are OCR'd and added to patient's timeline
- Patient gets notification + reminders automatically start

#### 1.3 **Caregiver User Journey**
```
INVITE → VIEW_PATIENT_PROFILE → RECEIVE_ALERTS → SUPPORT
```

- Caregiver invited by patient to view their profile (read-only or partial access)
- Caregiver sees simplified timeline: "Mom's appointments this week"
- Caregiver receives alert: "Mom missed her diabetes check-up. Remind her?"
- Caregiver can help schedule, set reminders, communicate with patient

#### 1.4 **Hospital/Administrator User Journey**
```
DASHBOARD_LOGIN → DEPARTMENT_VIEW → ANALYTICS → INSIGHTS
```

- Admin logs into **Hospital Operations Dashboard**
- Views:
  - Patient flow analytics (admissions by department, bed utilization)
  - Chronic disease population dashboard (how many diabetic patients, hypertensive, etc.)
  - Medication compliance trends across patient population
  - ER visit patterns (what brings patients back repeatedly?)
  - Doctor efficiency: avg time to prescribe, referral patterns
- **Use case:** "Our diabetic patients miss 40% of follow-ups. Let's auto-remind them via MediFlow"

## 2. MVP SCOPE (48-Hour Build)

### Tier 1: Must-Have (Essentials)
These are table-stakes features. Without these, the product doesn't work.

1. **Patient Signup & Auth**
   - Email/password signup
   - Simple profile (name, age, known allergies, chronic conditions)
   - ~2 hours (use Firebase Auth or Supabase)

2. **Document Upload & Storage**
   - File upload UI (drag-drop, camera, file picker)
   - Store in S3 / cloud storage
   - ~1 hour (use React dropzone + AWS S3 SDK)

3. **OCR Pipeline (AI Core)**
   - Use Google Cloud Vision OR AWS Textract to extract text from images/PDFs
   - Parse extracted text for:
     - Medications (Rx extraction)
     - Lab values
     - Dates
     - Doctor names
   - ~3-4 hours (API integration + regex/NLP parsing)

4. **Medication Conflict Detection (MVP Version)**
   - Simple database of common drug-drug interactions (top 50 combos)
   - When patient uploads meds, check against database
   - Flag conflicts with brief explanation
   - ~2 hours (load JSON, match, display alert)

5. **Patient Timeline**
   - Chronological feed of all uploaded documents
   - Group by type (meds, labs, appointments)
   - ~2 hours (sort, filter, render React components)

6. **Medication Reminders**
   - Basic reminder scheduling (send email, SMS, in-app notification)
   - Patient sets reminder time
   - ~1.5 hours (use Twilio for SMS or Firebase Cloud Messaging)

7. **Simple AI Summary for Doctors**
   - Template-based (not fully AI-generated in MVP)
   - Structured view of: allergies, meds, recent visits, labs
   - ~1.5 hours (pull data from DB, format, render)

**MVP Time Estimate:** ~13-14 hours (includes testing, deployment)
**Remaining Time:** ~34-35 hours for polish, AI sophistication, demos

### Tier 3: Out of Scope (Don't Build)
These eat time without proportional judge impact.

- ❌ Full EHR integration (hospital EMR connectors) → weeks of work, licensing issues
- ❌ Video consultations → better to integrate Zoom, takes time
- ❌ Prescription fulfillment / pharmacy ordering → regulatory nightmare
- ❌ Insurance claim processing → complex, no time
- ❌ Disease diagnosis or clinical decision support → liability, not MVP scope, violates value prop
- ❌ Multi-language support → i18n overhead for hackathon
- ❌ Mobile app (native iOS/Android) → web app is sufficient
- ❌ Advanced ML models (training custom models) → use APIs instead
- ❌ Full HIPAA compliance (legal review, BAAs) → state intent, audit logs, encryption-at-rest

## 3. WHAT NOT TO BUILD (Strategic Reasons)

### Guardrails to Avoid Scope Creep & Legal Risk

| Feature | Why NOT | Alternative |
|---------|--------|-------------|
| **Disease Diagnosis** | Liability + violates value prop ("doesn't diagnose") | Flag anomalies only; always say "discuss with doctor" |
| **Treatment Recommendations** | Requires MD review, can't do in 48h | Patient education only (what the drug does, not what they should take) |
| **Pharmacy Integration** | Regulatory (DEA, state boards), licensing | Show prescriptions; patient arranges pharmacy separately |
| **Insurance Claims** | Complex, requires insurance partner APIs | Out of scope for MVP; mention as future feature |
| **Real-time Telemedicine** | Video codec, compliance, server load | Use iframe to Zoom/Google Meet if needed |
| **Chronic Disease Monitoring** | Requires medical device integration | Let patients manually log vitals; don't auto-pull from Fitbit yet |
| **Clinical Guidelines Database** | Maintenance burden, rapid updates | Use public APIs (UpToDate, MedlinePlus) for links if time |
| **Multi-Hospital Federation** | Data governance nightmare | Single hospital/practice for MVP |

## 4. TECHNICAL RISKS & MITIGATION

### High-Risk Items (Likely Failure Points)

| Risk | Probability | Impact | Mitigation |
|------|-------------|--------|-----------|
| **OCR Accuracy** | High | Critical—bad OCR = garbage timeline | Use Google Cloud Vision (pre-trained, 95%+ acc). Have human fallback: "Confirm extracted meds?" |
| **LLM API Rate Limiting** | Medium | Demo fails during presentation | Cache responses. Pre-generate summaries during setup. Have fallback template summaries. |
| **File Upload Bottleneck** | Medium | Users wait >10s to upload | Async processing, progress bar. Show "Processing..." immediately, update when done. Use chunked upload for large PDFs. |
| **Drug Interaction DB** | Low (if using API) | Incorrect alerts → trust loss | Use FDA/RxNorm data, not homebrew DB. Test with known interactions. |
| **Database Schema Changes** | Medium | Deployment rollback needed | Plan schema upfront (Patient, Document, Medication, Lab, Timeline). Use migrations. |
| **Authentication/HIPAA** | High | Data breach = disqualification | Use managed auth (Firebase), encrypt data in transit + at rest. Don't store real patient data; use synthetic test data for demo. |
| **Latency (Doctor Summary)** | Medium | Summary takes 10s = feature feels slow | Pre-generate summaries on document upload. Show cached version immediately. |
| **Mobile Responsiveness** | Low | Works on desktop only | Test on phone early. Use responsive React components (Tailwind). |

### Technical Dependency Map

```
Frontend (React)
  ├─ Auth (Firebase)
  ├─ Upload UI (Dropzone + S3)
  ├─ Timeline View (Chronological component)
  └─ Doctor Dashboard (Summary view)

Backend (Node.js / Python)
  ├─ OCR Service (Google Cloud Vision)
  ├─ Text Parser (regex + NLP)
  ├─ Drug Interaction Checker (RxNorm API or local DB)
  ├─ LLM Service (OpenAI / Claude API for explanations & summaries)
  └─ Reminders (Twilio / Firebase Cloud Messaging)

Database (PostgreSQL / Firebase Realtime DB)
  ├─ Users
  ├─ Documents (raw uploads)
  ├─ Extracted Data (meds, labs, appointments)
  ├─ Timeline Events
  └─ Reminders

APIs (External Dependencies)
  ├─ Google Cloud Vision (OCR)
  ├─ OpenAI / Claude (LLM)
  ├─ RxNorm (drug data)
  ├─ Twilio (SMS reminders)
  └─ AWS S3 (file storage)
```

### Build-vs-Buy Decisions

| Component | Build | Buy (Use API) | Rationale |
|-----------|-------|---------------|-----------|
| **OCR** | ❌ | ✅ Google Cloud Vision | 48h not enough to train model; APIs are 95%+ accurate |
| **Drug DB** | ❌ | ✅ RxNorm / FDA OpenData | Maintained by FDA, always current, free |
| **LLM (Explanations)** | ❌ | ✅ OpenAI GPT-4 / Claude | Few-shot prompt engineering in 2h vs. weeks of fine-tuning |
| **Reminders** | ⚠️ Partial | ✅ Twilio / Firebase | Build scheduling logic (simple), outsource SMS/email delivery |
| **Auth** | ❌ | ✅ Firebase Auth | Don't build auth from scratch; 30 min setup |
| **Timeline UI** | ✅ | ❌ | Custom React component, core to UX, fast to build |
| **Conflict Detection** | ⚠️ Hybrid | ✅ API for accuracy | Use RxNorm for lookups + simple JSON rules for top conflicts |

```javascript
const buildSmartTimeline = async (patientId) => {
  const events = await getAllEvents(patientId); // docs, meds, labs, visits, etc.
  
  // Use simple heuristics + LLM to infer relationships
  const enriched = events.map((e, i) => ({
```

```javascript
      actionItems: ["Call doctor's office", "Schedule visit"]
    });
  }
  
  // Check medication duration
  for (const med of meds) {
    if (isMedicationDurationUnusual(med)) {
      insights.push({
        type: "med_concern",
        message: `You've been on ${med.name} for ${med.daysActive} days. Typical course is ${med.typicalDuration}. Confirm with doctor.`,
        actionItems: ["Contact doctor"]
      });
    }
  }
  
  return insights;
};
```

**Judge Impact:** 8/10 (preventive care + patient empowerment)
